# 优化建议书技术复审

复审对象：`docs/优化文档/_parts/part01~part07.md`（216 条改点 / P0 34 条）；代码基线 `radar_tool/` 20080 行。
方法：抽检 32/34 条 P0 逐条打开对应文件核对行号与行为，另核全局设施类"零命中"事实 6 项。

## 结论

**能不能照此派工**：可以，但必须先做五处修正——G-23 并入 CL-01、G-18 与 G-19 同版、IF-06/CA-01/G-23 降级、AR-02 与 CL-04 改法重写。抽检的 32 条 P0 中 29 条事实成立，问题集中在"改法依赖的函数行为"而非"痛点不存在"。
**主要风险**：三处"以为有其实没有"——`TaskSnapshot` 没有 `started_at/finished_at`（任务中心缺两列数据源）、`snapshots()` 没有清理 API、`fmt_sigma` 与 `transform_detail` 拿不到 `to` 系 unit；外加 `closeEvent` 被 G-01 与 ER-06 分别重写。
**是否建议放行**：建议有条件放行——一~四节的问题修完即可按 v1.1.2 派工，不建议整体退回重写。
