## 0. 这份规范要解决什么

### 0.1 用户原话的准确解读

> 「输出信息的格式化程度不足，看起来较为凌乱」

这里的「输出」**不是程序日志**，是界面上的信息呈现层：`指标计算器`的计算结果区、`阵列设计助手`的指标表、`测向校正`的三个 KPI 卡、`数据真值复核`的统计行、`格式转换`的徽章与预览表。用户看的是**数据怎么落到屏幕上**，不是数据算得对不对。

因此本文的验收对象是四个可判定的问题：

1. **主结果能不能在 1 秒内被找到**（层次）。
2. **同一列数字能不能竖着比**（格式与对齐）。
3. **换一个面板，读法是否一样**（一致性）。
4. **没有数据 / 出错 / 算一半时，界面说什么**（状态）。

## 1. 信息分层模型（全文地基）

### 1.1 一次输出的四层

任何一块"输出区域"里的信息，只能属于以下四层之一。**判断方法：如果这条信息被删掉，用户还能不能完成任务？** 不能删的是 L1，删了只是变麻烦的是 L2，删了只影响追溯的是 L3，删了不影响决策的是 L4。

| 层 | 名称 | 回答的问题 | 视觉承载物 | 字号/字重令牌 | 颜色令牌 | 字体族 | 允许出现的位置 | 同屏数量上限 |
|---|---|---|---|---|---|---|---|---|
| **L1** | **结论**（主结果） | "算出来是多少？" | `#resultCard` 的**主结果行**（V2 §4.5 第 2 段） | `--fs-32` 700 + 单位 `--fs-14` | `--n-900` + 单位 `--n-600` | 数值等宽 | 结果卡顶部、页头下方左起第一块 | **每屏 1 处**（每页 1 个主结果；同页多个计算器时，只有当前激活的那个有 L1） |
| **L2** | **关键指标** | "和它一起看哪几个数？" | KPI 卡（V2 §4.4）/ 指标表（V2 §4.6）/ 结果卡状态徽章（V2 §4.8） | `--fs-26` 700 / 表内 `--fs-13` | `--n-900` + 标签 `--n-600` | 数值等宽、标签中文 | L1 右侧或下方**相邻**位置 | KPI ≤ 4 张（1024 下 ≤ 2×2）；指标表 ≤ 8 行 × 8 列；徽章 ≤ 1 个 |
| **L3** | **支撑参数**（明细） | "这个数是怎么来的？" | `#resultCard` 的**参数表**（V2 §4.5 第 3 段）/ 明细表 / 折叠区 | `--fs-13` 400 | 标签 `--n-600`、值 `--n-800` | 值等宽、标签中文 | L1/L2 之下，或收进「更多参数 ▾」 | 可见 ≤ 8 行，其余折叠；明细表 ≤ 12 列 |
| **L4** | **提示与证据** | "要不要信它？有什么前提？" | `#hintBar`（info）/ `#errorBar`（danger）/ 公式区（V2 §4.5 第 4 段 + §4.13） | `--fs-12` 400 | `--info-text` / `--warning-text` / `--danger-text` | 中文（公式段可等宽） | **卡片底部**，永远是最后一段 | 每卡 ≤ 1 条提示 + 1 条错误；每条 ≤ 2 行（320px 卡内 ≈ 48 汉字） |

### 1.2 用户扫一眼应该先看到什么（可测）

把任意一页截图缩到 50% 再高斯模糊 6px，做**三级可读性测试**：

1. **第一眼（0~0.5s）**：必须能指出唯一一个"最大的数字块"。若指不出来，或指出两个，说明 L1 缺失或重复 → 违规。
2. **第二眼（0.5~2s）**：必须能数出 2~4 个"中等数字块"（L2）。
3. **第三眼（>2s）**：L3 在 L2 下方呈规则的行列，L4 在最底部呈一条色带。

**现状反例（05 页 · 指标计算器）**：`计算结果` 区是一个 200px 高的空白 `QTextEdit`，非空时里面全是 13px 同字号段落——四层被压成一层，第一眼只能看到蓝色渐变按钮。**这是最典型的"凌乱"**：不是脏，是**没有层次可供眼睛落脚**。

**现状反例（05 页 · 单位转换器计算结果）**：

```
转换结果                          ← h3，内联蓝（旧 calc_ui 硬编码色），比下面那行还大
10 Hz = 0.01 kHz                  ← 正文行，主结果和输入参数同字号
```

**正例（改造后）**：

```
计算结果                          [--fs-14 / --n-800 卡头]
0.01 kHz                          [--fs-32 / --n-900 等宽，L1]
─ 输入 ────────────────────────
输入值            10 GHz          [--fs-13 标签右对齐 / 值等宽，L3]
换算关系          λ = c / f       [--fs-13]
【hintBar】结果为按 c = 2.998×10⁸ m/s 计算的近似值。  [--fs-12 / --info-text]
```

## 2. 数值格式规则（工程师照着写 formatter）

### 2.1 唯一出口：新增 `radar_tool/fmt.py`

**规则 R0（最强的一条）：`radar_tool/` 下除 `fmt.py` 外，任何文件不得出现裸格式说明符。**

验收脚本（已按现库实测：改造前命中 205 处）：

```bash
grep -rEn ":\s*[0-9]*\.?[0-9]+[fge]|:g\}" radar_tool/*.py \
  | grep -v -e fmt.py -e game_panel.py | wc -l    # 目标：0
```

`fmt.py` 的公开接口（**纯规格，实现由工程师完成**）：

```python
# radar_tool/fmt.py
MISSING = '--'                       # 唯一缺省符（两个半角连字符）

def num(v, sig=3, *, unit=None, signed=False, missing=MISSING) -> str
    """主格式化器。按有效数字输出，自动选小数位。
    num(0.50504)                -> '0.505'
    num(29.9783, unit='mm')     -> '29.98 mm'
    num(42734, unit='km')       -> '42.7 km'      # 单位缩放由调用方先换算
    num(None)                   -> '--'
    num(15000.0)                -> '15000'
    num(-3.2, signed=True)      -> '-3.20'        # 成对出现时才用 signed
    """

def num_fixed(v, nd, *, unit=None, missing=MISSING) -> str
    """固定小数位，只给"按物理量类型定死小数位"的场合（dB、角度、百分比）。"""

def rng(lo, hi, unit=None, nd=None) -> str
    """区间。rng(-3.2, 1.8, 'dB') -> '-3.2 ~ 1.8 dB'"""

def delta(v, unit=None, nd=None) -> str
    """带符号变化量。delta(0.42,'dB') -> '+0.42 dB'；delta(-0.42,'dB') -> '-0.42 dB'"""

def thresh(op, v, unit=None) -> str
    """阈值。thresh('<',0.1,'dB') -> '< 0.1 dB'；thresh('>=',3.5,'dB') -> '≥ 3.5 dB'"""

def count(n, unit='') -> str
    """计数。count(1280,'样点') -> '1280 样点'；整数不分组（N13），不加千分位/空格"""

def pct(ratio, nd=1) -> str
    """pct(0.432) -> '43.2%'"""
```

**`num()` 的有效数字算法（工程师照抄）**：

```
x = abs(v)
if x == 0 or 1 <= x < 10**sig:      nd = sig - 1 - floor(log10(x))    # 3 位有效
elif x >= 10**sig:                   nd = 0
else:                                # x < 1
    nd = sig - 1 - floor(log10(x))
nd = clamp(nd, 0, 6)                 # 最多 6 位小数，绝不出现 6 位以上
s = f'{round(v, nd):.{nd}f}'         # 先舍入再输出，绝不截断
strip trailing zeros only when nd > 0 and nd was auto-chosen
```

### 2.2 按物理量定死小数位（覆盖 `num()` 的自动选择）

| 物理量 | 规则 | 正例 | 反例（现库实例） |
|---|---|---|---|
| 长度 / 距离（m、mm、cm 级） | 3 位有效，换到最贴切的量级 | `0.505 m`、`29.98 mm` | `0.505000 m`、`29978.300000 mm` |
| 距离（km 级） | 数值换到 km，1 位小数 | `42.7 km` | `42734.000000 m` |
| 频率 | 换到 GHz/MHz/kHz，3~4 位有效 | `10.0 GHz`、`2.40 GHz`、`128 kHz` | `10000000000.0 Hz` |
| 波长 | mm，3 位有效；λ 符号独立 | `29.98 mm`、`0.10 λ` | `0.0299783 m` |
| dB 类（增益/损耗/SNR/余量/隔离度） | **固定 1 位小数** | `12.4 dBi`、`-3.2 dB`、`6.8 dB` | `12.4000 dBi`、`12.43627 dB` |
| 角度（方位/俯仰/波束宽度） | **固定 1 位小数** | `35.0°`、`6.4°` | `34.999999°` |
| 角度误差 / σ（度） | 2 位小数 | `0.42°` | `0.420000°` |
| 角度误差 / σ（角秒） | 1 位小数 + `″` | `1.8″` | `1.8"`（直角引号） |
| 相位 | 1 位小数，归一化到 (-180°, 180°] | `-75.0°` | `285.0°` |
| 幅度（无量纲视在幅度） | 2 位小数 | `0.87` | `0.870000` |
| 坐标 (x, y, z) 单位 m | **3 位小数** | `0.125 m` | `0.125000`（04 页表格现状 6 位） |
| 坐标 单位 mm | 1 位小数 | `194.5 mm` | `194.500000` |
| 比例 / 百分比 | 1 位小数 + `%` | `43.2%` | `0.432` |
| 计数（样点/帧/条/个） | 整数，**不加任何分组符** | `1280 样点` | `1280.0 点`、`1 280`、`1,280` |
| 电压 / 功率小量 | 换到 μV/mV、mW，3 位有效 | `0.32 μV`、`-92.4 dBm` | `0.00000032 V` |
| 时间 | s / ms / μs 换量级，3 位有效 | `128 ms`、`1.28 s` | `128.000 ms` |
| 版本号 | 原样 | `v1.1.1` | — |

> **量级换算是格式化的一部分，不是业务逻辑的一部分。** `fmt.py` 提供 `scale(v, from_unit, to_unit)` 的调用位（具体换算复用 `calc_units.py` 已有实现），面板里只写 `fmt.num(u.convert(x,'m','km'), unit='km')`，不写 `x/1000`。

| **N10** | 极值/超差用**徽章 + 文字**表达，禁止 🔴🟡🟢 染色 | `calc_ui.py:568-571` `'🟢 链路余量充足' / '🟡 余量临界' / '🔴 链路不足'` | `set_status('余量充足','success')` + `set_hint('info','余量 6.8 dB，满足 3 dB 门限')` |

### 2.4 科学计数法的唯一用法（阈值是硬的，且被测试锁定）

**允许区间：只有 `|x| ≥ 1e6` 或 `|x| ≤ 1e-4` 时才允许科学计数；其余一律定点输出。**

| 量级 | 允许的写法 | 说明 |
|---|---|---|
| `1e-4 < \|x\| < 1e6` | **定点**（`fmt.num`） | 这是 99% 的界面数值。`1000`、`42734`、`0.02998` 都在此区间 → 必须定点 |
| `\|x\| ≥ 1e6` | 先换单位（优先）→ `1.28 MHz`、`427 km` | 换不了才写 `1.23e6` |
| `\|x\| ≤ 1e-4` | 先换单位（优先）→ `0.32 μV`、`29.98 nm` | 换不了才写 `1.23e-5` |

规则细则：
1. **优先换单位**（`2.99792e-08 m` → `29.98 nm`、`1e-9 s` → `1 ns`）。
2. 确实无法换（如 `1/c` 的中间量）时，写成 `1.23e-5`：`e` 小写、**指数不带 `+`、不带前导零**。禁止 `1.230000e-05`、禁止 `1.23×10^-5`。
3. **禁止把落在定点区间的值改写成科学计数**：`1000` 不得变成 `1.0×10³` 或 `1e3`；`-90` 不得变成 `-9.0e1`。这三条都有单测断言锁着（`tests/test_unit_conversion.py:72`、`tests/test_df_accuracy.py:95-96`），改了就红。
4. 科学计数**不得出现在表格列里**（会破坏右对齐）；只能出现在 L3 参数值或公式区。

### 3.1 公开方法（完整签名，含语义与失败行为）

```python
class ResultCard(QFrame):
    def __init__(self, parent=None, *, title='计算结果')
        """紧凑模式由**容器宽度自动判定**（< 360px）：主值降为 --fs-26、参数表 1 列。
           不提供手工开关 —— 手工传参会让同一页出现两种主值字号（V2 §4.5
           已固化为 `QLabel#resultValue[dense="true"] { font-size: 19.5pt }`）。"""

    # ---- 标题 ----
    def set_title(self, text: str) -> None
        """卡头文字。--fs-14 / --n-800。空字符串则隐藏卡头行。"""

    # ---- L1 主结果 ----
    def set_primary(self, value, unit=None, *, note=None,
                    status=None, copyable=True) -> None
        """value: str|float|None。float 必须已过 fmt.num()，本方法不负责格式化。
           value=None  -> 进入空态（等价 set_empty，prompt 沿用上次）
           unit        -> 独立 QLabel，--fs-14 / --n-600，与 value 底部基线对齐
           note        -> 主结果右侧的补充短语，--fs-12 / --n-600，例：'(= 32.4 dBi)'
           status      -> tuple[str, tone]，等价于 set_status，图标位在卡头右侧
           copyable    -> 是否显示「复制」ghost 按钮（V2 §4.7）"""

    # ---- L3 参数表 ----
    def set_params(self, pairs, *, group=None, collapsible_over=8,
                   empty_text=None) -> None
        """pairs: list[tuple[str, str]]，str 已格式化（含单位）。
           渲染为 2 列：标签列固定 96px 右对齐（--fs-13/--n-600），
                       值列等宽左对齐（--fs-13/--n-800），行高 `--row-param`（24px）。
           group: 可选分组名，非 None 时在参数表内插入分组头（--fs-12s/--n-600）。
           len(pairs) > collapsible_over 时折叠，显示「更多参数（+N）」ghost 按钮。
           empty_text: pairs 为空时在此位置显示 --n-500 的说明（默认 MISSING）。"""

    # ---- L2 状态徽章 ----
    def set_status(self, text, tone='neutral') -> None
        """tone ∈ {neutral, primary, success, warning, danger}，
           映射 V2 §4.8 的 #badge[tone=...]。text ≤ 6 汉字，不放动词、不放图标。"""

    # ---- L4 提示 ----
    def set_hint(self, kind, text) -> None
        """kind ∈ {'info','warning','danger','none'}。
           info    -> #hintBar，--info-bg 底 + 左 3px --info 条 + --info-text
           warning -> #hintBar[kind=warning]，--warning-bg / --warning / --warning-text
           danger  -> #hintBar[kind=danger]（视觉等价 §4.13 #errorBar，但语义不同：
                      前者是"整卡结论"，后者是"贴在控件旁的字段校验"。二者不得同屏
                      同时出现，否则同一个错误会被说两遍）
           none    -> 整条隐藏且不占高度
           text 最多 2 行（320px 卡内 ≈ 48 汉字，全宽卡 ≈ 76 汉字）；超出则自动
                 截断为 1 行 + 「查看全部」。"""

    # ---- 四个生命周期状态（互斥，任一方法调用即切换） ----
    def set_empty(self, prompt, *, hint=None) -> None
        """空态：主值位显示 --（--n-500 等宽），参数表整列 --n-500，
           提示条换为 --n-100 底 + --n-600 字的 prompt（V2 §4.5 状态条）。
           prompt 必须是"下一步动作"：「录入参数后自动计算」「选择数据文件后显示统计」
           hint 为补充一行，可省略。"""

    def set_loading(self, text='正在计算…', *, progress=None) -> None
        """加载态：主值位显示 text（--fs-17 / --n-600），参数表禁用色，
           progress 非 None 时在主值下方显示 #kpiAccent 同规格的 6px 进度条（V2 §4.11）。"""

    def set_error(self, reason, *, retry_callable=None, detail=None) -> None
        """错误态：主值位显示「计算失败」（--fs-17 / --danger-text），
           提示条换 #errorBar，reason 一句话（≤ 40 汉字），
           detail 走「查看详情」（只读 QPlainTextEdit 对话框），
           retry_callable 非 None 时在提示条右端出「重试」ghost 按钮。"""

    def set_partial(self, ok, failed, *, failures=None, retry_callable=None) -> None
        """部分成功：主值位显示「{ok} 成功 / {failed} 失败」（failed 数字用 --danger-text），
           徽章 tone=warning，提示条 warning 文案，
           failures=[(对象名, 原因)] 时折叠成「失败明细（N）」。ok+failed 必须等于总数。"""

    # ---- 辅助 ----
    def clear(self) -> None            # 回到 set_empty(上次 prompt)
    def toPlainText(self) -> str
        """【强制，测试兼容】把当前可见文本按阅读顺序平铺为纯文本。
           顺序：卡头 → 主值 + 空格 + 单位 → 徽章 → 参数 (k, v) 逐行 → 提示/错误。
           详见 §3.6。禁止返回 HTML、禁止插入全角空格做对齐。"""
    def render_legacy(self, lines)     # 【仅迁移期】解析旧 ## / ** / emoji 协议，见 §3.4
```

### 3.3 状态机（四态互斥，所有迁移必须走这张表）

```
        ┌────────── set_empty(prompt) ◄── clear()
        ▼                                      ▲
   [EMPTY] ──set_primary()──► [RESULT] ──set_primary()──► [RESULT]
        │                        │

[hint/error 文案]      ← 最后一行为当前提示或错误原因，原样输出
```

示例（单位转换，`1 rad → mrad`）：

```
单位转换
1000 mrad
输入值 1 rad
换算关系 1 rad = 1000 mrad
```

示例（测向精度，`θ=95°` 奇异态）：

```
测向精度
计算失败
来波方位 95.0°
基线 d/λ 0.50
相位误差 5.0°
来波方向必须在 -90° ~ 90° 之间，当前为 95°
```

**四条实现细则**：
1. **行分隔用 `\n`**，不用 `\r\n`、不用 `\u2028`。
2. **只返回"可见"内容**：折叠的「更多参数」里未展开的项**也要返回**（否则用户复制不全，测试也可能依赖）；但 `set_hint('none')` 时的空提示条不返回空行。
3. **禁止返回 HTML 标签**；禁止为了对齐插多个连续空格或全角空格（`\u3000`）——`toPlainText()` 的消费者是测试断言和剪贴板，不是终端表格。
4. `clear()` / `set_empty()` 后仍要返回**非空**的卡头 + 空态提示句（见 3.6.4）。

#### 3.6.3 文案原样保留规则（**不得"精简"掉**）

测试断言的是**子串**，所以任何"文案重写/精简/术语替换"都可能让测试红。以下 9 个词在对应场景下**必须原样出现在 `toPlainText()` 里**：

| 必须出现的子串 | 出现场景 | 来源 | 测试 |
|---|---|---|---|
| `必须大于` | 任何"参数必须为正"的校验失败 | `safe_exception_message(exc)` 的原始消息，如 `'功率必须大于 0'` | `test_unit_conversion.py:82`、`test_calc_link_budget.py:87` |
| `必须大于 0` | 倍数 → dB 且倍数为 0 | 同上 | `test_unit_conversion.py:82` |
| `频率` / `功率` / `带宽` / `距离` / `码率` | 对应参数校验失败时的错误文案 | 异常消息里带参数中文名 | `test_unit_conversion.py:90,97,104`、`test_calc_link_budget.py:80-88` |
| `-90` 与 `90` | 来波方位超界（θ=95°） | 错误文案里的合法区间 `-90° ~ 90°` | `test_df_accuracy.py:95-96` |
| `接近正侧射` | θ=89.9° 的侧射警告 | 原 `error_line` 文案（现 `calc_ui.py:665`） | `test_df_accuracy.py:100` |
| `重新执行` | 真值复核的预处理已失效 | `compare_data.py:543` `'雷达预处理已变化，请重新执行第 1 步粗对齐。'` | `test_truth_review_panel.py:443` |
| `结果已清除` | 干涉仪页点「清除」 | `interferometer_sim.py:1251` `'结果已清除。'` | `test_qt_panels.py:153` |
| `1000` | 1 rad → mrad | 主值 `1000` + 单位 `mrad` | `test_unit_conversion.py:72` |

**规则**：
- **错误文案直接透传 `safe_exception_message(exc)` 的原文**，允许在前面加"什么错"、后面加"怎么办"，但**不得删改原文中的任何词**。
  正例：`输入值无效：带宽必须大于 0 → 请填写 1 ~ 1000 MHz 之间的数值`
  反例：`参数不合法`（把原因吃掉了，测试与用户双输）
- **警告类文案（`接近正侧射`、`奇异`、`重新执行`）必须落在 `set_hint` 或 `set_error` 的 text 里**，不允许只做成徽章文字（徽章限 6 字，装不下）。徽章可以同时存在。
- **参数表的 key 保留原名**（`频率`、`功率`、`带宽`），不要为了排版改成 `工作频率 (GHz)` 而丢掉原词——`频率` 是 `工作频率` 的子串，安全；但改成 `Freq` 就会挂。

#### 3.6.4 清除态/空态用 `set_empty(prompt)`，并且提示句必须原样

| 场景 | 正确调用 | 验收 |
|---|---|---|
| 干涉仪「清除」按钮（`interferometer_sim.py:1251`） | `set_empty('结果已清除。')` | `toPlainText()` **精确等于** `'结果已清除。'`（若卡头非空会导致精确相等失败 → 该控件必须 `title=''`，即无卡头行） |
| 真值复核预处理失效（`compare_data.py:543`） | `set_empty('雷达预处理已变化，请重新执行第 1 步粗对齐。')` | `toPlainText()` 含 `'重新执行'` |
| 计算器初始/清空 | `set_empty('录入参数后自动计算')` | `toPlainText()` 含该句 |

> **注意这条陷阱**：`test_qt_panels.py:153` 是 `==` 精确比较，不是 `in`。所以 `txt_stats` 若要改造成 `ResultCard`，必须满足「无卡头 + 只有一行提示」时输出恰好 `'结果已清除。'`（末尾无换行）。**最省事的做法是 `txt_stats` / `txt_cmp_stats` 本期不改造，保持 `QTextEdit`**，只改 `calc_ui` 的 7 个计算器——它们全是 `assertIn`，宽松得多。

#### 3.6.5 数值不得因格式化而改变可断言的子串

| 输入 | 必须能被 `assertIn` 找到 | 说明 |
|---|---|---|
| 1 rad → mrad | `1000` | `fmt.num(1000.0)` 输出 `1000`（N13 禁分组、N14 禁科学计数） |
| θ = 95° | `-90` 和 `90` | 错误文案里的区间写成 `-90° ~ 90°`，不是 `−90° ~ 90°`（**注意：负号必须是半角连字符 `-`，不是 U+2212 减号 `−`**） |
| θ = 89.9° | `接近正侧射` | 文案保留 |
| 任意 dB 值 | 允许 `6.8`、`-3.2` | 1 位小数不影响子串 |

> ⚠️ **负号陷阱（V2 §8 第 18 条）**：**本文档与代码里一律用半角连字符 `-`（U+002D）表示负号、区间连接与公式减号**；禁止用 `−`（U+2212）、`–`（U+2013）、`－`（U+FF0D）冒充。`fmt.num()` 只输出 U+002D，排版层不得做任何字符替换。
> **例外**：中文破折号 `——`（U+2014）作**标点**是合法的（如「结果在第二页——精对齐之后」），但不得当减号用。
> 本文档已按此归一（全文 `−` 只保留在"反例示例"里）；如果看到任何数值位置还有 `−`，**按 U+002D 实现**。
> 视觉上 hyphen 在 Consolas 里落在字面中部、宽度与等宽格对齐，参数表列不会因此错位——安全性优先，这笔账划算。

### 4.2 场景 B：多指标结果（天线增益 / 链路预算，`05` 页）

### 4.3 场景 C：统计量汇总（数据真值复核，`01` 页）

**结构**：不用 6 个句子，用**2 列表 + 1 个差值徽章**。标签右对齐固定 96px，数值等宽左对齐，单位进表头。

**示例文案**：标签 `雷达原始` / 值 `1280` / 单位进表头 `样点`。**注意：值列只放数字，`样点` 放表头 `数量 (样点)`。**

四个问题：① 6 个 `QLabel` 同一字号同一色，无层级；② 标签与数值在同一字符串里，**数字无法竖着比**（V2 P4）；③ 冒号用半角、混排无空格；④ 第 3 行单独一个 `GPS 对齐后有效` 被塞在 row 7 col 2，与前两行不成栅格（`compare_analysis.py:328`）。

### 4.4 场景 D：指标表（阵列设计助手，`04` 页）

**结构**：`QTextEdit + 空格填充` → **真 `QTableWidget`（3 列，单位进表头）或 2 列表格 + 说明列**。列类型按 V2 §4.6 的**列类型表**取（文本 / 数值 / 状态 / **说明**四种），禁止自定义。

```
⬚ QTableWidget（#指标表，3 列，行高 --row-table）
  指标            数值      说明（--fs-12 / --n-600 / 左对齐 / elide right）
  阵列类型        均匀线阵   ULA
  阵元数          8          --
  阵列增益        15.1 dBi   近似 10·log₁₀N + 3
  3dB 波束宽度    6.4°       50.8 / (N·d/λ)
  第一副瓣电平    -13.2 dB   左 -13.2 / 右 -13.2
  无模糊范围      ±30.0°     构型相关
  阵列孔径        3.50 λ     构型相关
  ▸ 栅瓣（2 行，折叠）
```

**数值列右对齐 + 等宽；`指标` 列左对齐 + 中文；「—」不允许出现（N6）**：`说明` 为空时写 `--`。

**说明列的 5 条硬约束**（V2 §4.6 列类型表已固化，此处只重申落地要求）：
1. `--fs-12 / --n-600`，**不得与数值列同字号同色**——说明列是"这个数怎么来的"（如 `近似 10·log₁₀N + 3`），必须主动退到二级，否则整表失去读数秩序。
2. 左对齐，最多 2 行，超出 `elide right` + `setToolTip(全文)`。
3. 最小宽 160px，`1fr` 弹性；不得被 `Stretch` 均分压迫到 160 以下。
4. 单元格内容为**纯文本**，不得嵌 HTML、不得放 `QPushButton`（要操作就用右键菜单或行尾固定按钮列）。
5. 空说明写 `--`，不写"无"、不写 `-`、不写空白（N6 同一条规则）。

> 另：**多列信息一律不许用字符串填充对齐**，这是 V2 §4.5.1 的独立禁令，也是本场景反例的根因（下面的 `─` 实线与空格填充）。两条规范在此完全一致，验收共用一条命令：`grep -rn '"─"' radar_tool/` 必须为 0。

**反例**（`array_designer.py:766-778` 现状，屏幕上是这个样子）：
```
指标               数值 说明
──────────────────────────────────────────────────────────────
阵列类型                   均匀线阵
阵元数                            8
阵列增益                15.1 dBi 近似 10log10(N)+3
3dB波束宽度             6.4° 50.8/(N·d/λ)
```
根因两条：① `f'{"指标":<16}'` 用**字符数**填充，而中文是双宽字符——`阵列类型`（4 字=8 显示列）补到 16 字符 = 20 显示列，`3dB波束宽度`（11 显示列）补到 16 字符 = 19 显示列，**两者永不相等**；② `f'{"─"*62}'` 是一条比内容更宽的实线，在 `QTextEdit` 里被折行后与下一行重叠。

**硬规则**：**禁止用空格/制表符/`─` 在等宽文本里做表格**。中文双宽 + 字体回退（`QFont('Consolas', 9)` 里中文会回退到宋体）让这类对齐在 Windows 上不可能正确。表格就用 `QTableWidget`，V2 §4.6 已有全部样式。

### 4.6 场景 F：长文本状态 / 日志（校正、账本、试验记录）

**结构**：只读 `QPlainTextEdit`（**不是 `QTextEdit`**），`--s-inset` 底 + 1px `--n-200`，等宽 `--fs-12`，限高 5 行（≈ 100px），右侧/顶部「查看全部」打开对话框。

### 4.7 场景 G：部分成功（N 成功 M 失败）

**结构**：`set_partial(ok, failed)`

```
⬚ #resultCard
├ L1  转换结果                                  [右] #badge 部分成功 warning
├     [ --fs-32 ] 126  [ --fs-14 ] 帧成功   [ --fs-17 --danger-text ] 2 帧失败
├ ─── 失败明细（2）▸ ───
│     第 47 帧   量化值 0.35 超出 int16 范围
│     第 103 帧  行长度 61 ≠ 64
└ L4  #hintBar warning：失败帧未写入输出文件，其余 126 帧已保存至 tr_all_inject.bin。
```

**硬规则**：
- **主值位必须是"成功数"，失败数是次要但必须同屏可见**（不能用 `QMessageBox` 弹窗说完就消失）。
- 失败明细默认折叠、可复制。
- 只要有失败，徽章 `tone` 必须是 `warning` 或 `danger`，**不允许** `success`。
- `ok + failed == total` 必须成立，否则按 `set_error` 处理（自相矛盾的状态比没有状态更糟）。

### 4.10 场景 J：错误态

**结构**：`set_error`

```
⬚ #resultCard
├     计算失败                                   [右] #badge 失败 danger
├ L4  #errorBar：输入值不是数字（"abc"）        [右 ghost] 重试  [ghost] 查看详情
```

**规则**：
- 错误文案三段式：**什么错 + 为什么 + 怎么办**。至少要有"什么错"和"怎么办"。
  - ❌ `❌ 无效输入`（现状 `calc_ui.py:325` `f'❌ {safe_exception_message(exc)}'`）
  - ✅ `输入值不是数字（"abc"）→ 请填入 0.01 ~ 1000 之间的数值`
- **禁止 `QMessageBox` 报计算错误**（模态框打断流程；V2 §4.13 只允许保留模态用于文件覆盖等破坏性确认）。
- 输入框本身同步 `setProperty('state','error')`（V2 §4.9 `QLineEdit[state="error"]`），与错误条一一对应；**同一错误只在一处显示**（输入框描边 + 错误条属于同一处，允许；错误条 + 状态栏 + 弹窗 = 三重，禁止）。
- **`#errorBar` 与 `#hintBar[kind="danger"]` 不得同屏**（V2 §4.5）：二者视觉等价但语义不同——`#errorBar` 是"贴在控件旁的字段校验"，`#hintBar[kind=danger]` 是"整卡结论"。同屏出现等于把同一个错误说两遍。**规则**：字段级校验失败用 `#errorBar` + `QLineEdit[state="error"]`；整卡无法产出结果用 `set_error()`（主值位「计算失败」+ `#hintBar[kind=danger]`），二者择一。
- 错误条 ≤ 2 行；超长进「查看详情」。

**现状问题**：`calc_ui.py` 的错误走 `_show_result(['❌ …'])`，结果是 200px 空白里一行 13px 红字 → 视觉重量与「计算失败」这件严重事件不匹配。

## 5. 布局缺陷修正规范

### 5.1 量化基线：宽度公式（所有栏宽与文案长度的判定依据，直接算）

**字形宽度（Windows / Microsoft YaHei UI + Consolas，96 DPI 实测基准）**

| 内容 | 字号 | 单字符宽度 |
|---|---|---|
| 汉字（`--fs-13` / 10pt） | 13 px | **13 px** |
| 汉字（`--fs-12` / 9pt） | 12 px | **12 px** |
| 西文/数字（等宽 `--fs-13` / 10pt） | 13 px | **7.2 px** |
| 西文/数字（等宽 `--fs-11` / 8.5pt） | 11 px | **6.1 px** |
| 徽章/表头汉字（`--fs-12s` / 9pt） | 12 px | **12 px** |

**按钮自然宽度**

```
W_btn = 13·n_cjk + 7.2·n_latin + 28 (padding) + (22 if icon) + 2 (border)

例：「保存范围预设」  n_cjk=6  icon  → 78 + 50 = 128 px
    「按当前范围重绘对比图」n_cjk=10 icon → 130 + 50 = 180 px
    「重绘」        n_cjk=2  icon  → 26 + 50 = 76 px
```

**栏内可用宽度**

```
A_col = W_col - 10 (组框左 padding) - 10 (右) - 2 (描边) - 10 (滚动条预留)
      = W_col - 32

两个按钮并排（间距 --sp-4 = 8）：
    2·(13n + 50) + 8 ≤ A_col   →   n ≤ (W_col - 140) / 26
```

**这张表就是「150px 栏宽下最多几个字」的答案，也是工程验收的唯一依据**：

| 栏宽 `W_col` | 可用宽 `A_col` | 单按钮纵排<br>最多汉字（带图标）<br>`(A-50)/13` | 单按钮纵排<br>最多汉字（无图标）<br>`(A-30)/13` | **两按钮并排**<br>每个最多汉字<br>`(W-140)/26` | 判定 |
|---|---|---|---|---|---|
| **150 px** | 118 | **5** | 6 | **0** → 不可行 | 一个栏宽 150 的左栏**绝不能**放两个并排文字按钮 |
| **180 px** | 148 | 7 | 9 | **1** | **窄栏阈值**：< 180px 按 W2b 处理 |
| 200 px | 168 | 9 | 10 | **2**（`保存` `重绘`） | 只允许 2 字以内的并排文案 |
| 240 px | 208 | 12 | 13 | **3** | 「保存」「重绘」「清空」级别 |
| **280 px**（V2 §5 表单卡下限） | 248 | 15 | 16 | **5** | 「应用过滤」「清除过滤」可并排 |
| **320 px**（表单列下限；含 ≥4 数值列的表格卡取 **340**） | 288 / 308 | 18 / 21 | 19 / 22 | **6** / 6 | 推荐的最低栏宽；340px 时 4 个 72px 数值列仍放得下 |
| 420 px | 388 | 26 | 27 | **10** | 「保存范围预设」+「按当前范围重绘对比图」= 128+180+8 = 316 ≤ 388 ✅ 可行 |

**由公式得出的三条硬规则**

| 编号 | 规则 |
|---|---|
| **W1** | **左栏（表单列）`setMinimumWidth` ≥ 320px；若该栏内含 ≥4 个数值列的表格，≥ 340px**（4 列 × 72 数值列下限 = 288，加上左右内边距与滚动条后需 320 才不截断，留 20px 余量取 340）。并排两个按钮时，栏宽必须满足 `W ≥ 26·n + 140`（n = 较长那条文案的汉字数）：两个 4 字按钮需 244px，两个 6 字按钮需 296px，「保存范围预设」+「按当前范围重绘」（6+10）需 400px。**算不出来就不许并排。** V2 §5 的「表单卡 280」是不含并排按钮、也不含宽表格的场合。 |
| **W2** | UI 按钮文案 **≤ 6 汉字**（`--fs-13` 下 78px + 图标 = 128px，两列布局下安全）。超 6 字必须：缩到 6 字内 / 改 `variant="ghost"` 只留图标 + tooltip / 移到宽度足够的区域。 |
| **W2b** | **窄栏硬规则：栏宽 < 180px 时，按钮文案上限 6 汉字，且禁止两个文字按钮并排**（公式给出 150px 下并排上限 = 0 字，200px 下 = 2 字）。超出时只允许两种降级：① 缩成短文案（≤ 6 字，全句进 `setToolTip`）；② 把按钮移出该栏（移到下方宽度足够的组框，或页头）。**禁止靠减小字号、减小 padding 或裁切文字来"塞下"**——三条都会导致下一节 ① 的压字。 |
| **W3** | 任何 `QHBoxLayout` 里的按钮组，代码里必须能算出"最坏自然宽度 ≤ 父容器最小宽度"。做不到就换 `QVBoxLayout` 或折叠进「更多 ▾」。 |

col_min(header, cells, kind='num'):
