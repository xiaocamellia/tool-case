## 1. 背景与动机

### 1.1 现状痛点

卫星载荷研制过程中，坐标系数量多、层级深、耦合强：

- **惯性与轨道层**：J2000 惯性系、ECEF 地固系、LVLH 轨道系
- **平台层**：本体坐标系（BCF）、星敏光轴系、陀螺系、太阳敏感器系
- **载荷层**：相机视轴系、SAR 波束中心系、激光通信终端系、数传天线波束系
- **结构与变形层**：安装基准系、热变形后的实际载荷系

这些坐标系及其相互变换关系目前分散存在于：结构设计图纸（安装矩阵）、整星标定报告（光轴交联标定结果）、算法代码（散落各处的变换公式与"魔法数字"）、测试记录（标定点对与残差）。

**带来的具体问题：**

1. **无单一事实源**：同一变换在不同文件中数值不一致，且设计值与标定值并存时，无法判断哪个是当前有效值
2. **无自动计算**：任意两系之间变换需人工推导拼接，易错且不可复用
3. **无直观呈现**：光轴朝向、波束方向、载荷间相对关系只能靠想象
4. **无误差追踪**：知道每个标定有误差，但不知道合成到最终指向误差是多少
5. **无复核手段**：标定后与设计值对比、环路是否闭合、夹角是否达标，全靠人工作业
6. **无集中交付物**：评审时坐标系关系散落在各处文档中

### 1.2 目标定位

构建**坐标系账本**子模块，将"坐标系"作为图的节点、将"变换关系"作为**带误差、带来源、带状态的边**，实现：

> 集中记录全部坐标系与变换关系 → 自动计算任意两系变换 → 矢量跨系表达 → **设计/实测对比与环路复核** → 载荷指向计算与误差预算 → 3D 可视化 → 报告导出

一句话定位：**一份账本 + 一个计算器 + 一套复核 + 一张图 + 一份报告。**

### 1.3 不是什么

为避免定位漂移，本模块不做：

- 不做轨道动力学仿真（STK / GMAT 的事）、不做姿态控制仿真
- 不做高精度天文转换（章动、岁差、EOP）——预留接口
- 不做凭证、经手人、审计日志流——来源标注（`source` 字段）≠ 审计系统，前者是数据的一部分，后者是流程系统
- 不做温度→变形的物理建模——但**允许**把不同工况下的实测值作为多条状态记录入账

本模块只做载荷研制内部的**坐标系基准管理与复核**。

## 2. 术语与全局约定

### 2.1 核心语义

**变换矩阵 `T_A_B`** 是全局唯一约定，贯穿设计、界面、导出与文档：

```
T_A_B  表示"把 B 系下的量变换到 A 系"
p_A = T_A_B · p_B
```

| 操作 | 公式 |
|---|---|
| 拼接 | `T_A_C = T_A_B · T_B_C` |
| 求逆 | `T_B_A = inv(T_A_B)` |
| 闭合 | `T_A_B · T_B_A = I` |
| 环路 | `T_A_B · T_B_C · T_C_A ≈ I`（复核依据，见 8.4） |

配置中 `from` / `to` 字段含义为 `T_to_from`：

```json
{ "from": "body", "to": "camera_panchro",
  "//": "含义：把 camera_panchro 系的点变换到 body 系，即 T_body_cam" }
```

> 界面与报告中一律双写法显示：`T_body_cam（camera_panchro → body）`，防止只看下标误读方向。

### 2.2 必须显式声明的约定

"约定不统一"是坐标系工具最大的杀手。以下约定必须在账本中**显式声明**，缺省即报错，绝不猜测：

| 约定项 | 可选值 | 缺省行为 |
|---|---|---|
| 欧拉角顺序 | ZYX / XYZ / ZYZ / …（12 种） | **必填**（当 rotation.type = rpy） |
| **欧拉角旋转类型** | `intrinsic`（内旋）/ `extrinsic`（外旋） | **必填**（v2.0 新增，v1.0 遗漏） |
| 四元数顺序 | `[w,x,y,z]` / `[x,y,z,w]` | 全局统一 wxyz，可覆盖 |
| 角度单位 | deg / rad | 必填 |
| 长度单位 | m / mm | 必填 |
| 轴向约定 | `Z_UP` / `Z_FORWARD` / `Y_UP` / `NED` / `ENU` | **必填** |
| 手性 | right / left | 缺省 right |

**scipy 映射陷阱（由本模块统一消化）**：`scipy.spatial.transform.Rotation.from_euler` 中**小写序列为内旋、大写为外旋**。账本中的 `order: "ZYX"` + `euler_rotation: "intrinsic"` 由 `conventions.py` 显式映射为 scipy 的 `'zyx'`，映射规则封装在一处，业务代码不得直接传序列字符串给 scipy。

### 2.3 内部计算标准

| 项 | 标准 |
|---|---|
| 数值精度 | 双精度浮点（float64） |
| 变换表示 | 4×4 齐次矩阵（numpy `ndarray`） |
| 姿态内部表示 | `scipy.spatial.transform.Rotation`（原生 xyzw）；账本边界按 2.2 约定转换 |
| 内部单位 | m + rad |
| 进出口 | 按账本配置单位换算（复用 `calc_units`） |
| 误差模型 | **各向同性 σ + 各段独立**，`σ_total = √(Σσᵢ²)`；假设显式写入报告页脚（见 12.3） |

| 角色 | 核心诉求 | 主要操作 |

| 载荷设计师 | 光轴指向、载荷间关系、误差预算、**复核** | 录账、查变换、对比、指向计算、出报告 |

### 4.2 分层设计

```
┌────────────────────────────────────────────────────────────┐
│ 交付层   coord_ledger_panel（PyQt5）│ 报告导出 │ 3D 视口     │

│ 应用层   变换查询│矢量跨系│指向计算│误差预算│对比/环路/限值   │
├────────────────────────────────────────────────────────────┤
│ 求解层   图构建│路径搜索│矩阵合成│预计算缓存                │
├────────────────────────────────────────────────────────────┤
│ 基础层   4×4矩阵│姿态互转（scipy）│单位换算（calc_units）    │
├────────────────────────────────────────────────────────────┤
```

**依赖方向约束**：`coord_core` 不得 import PyQt5 / pyvista / matplotlib；`coord_ledger_panel` 与 `coord_3d` 只能单向依赖 `coord_core`。此约束保证核心可独立测试、可被脚本调用（承接 v1.0"核心不依赖 GUI"的非功能需求）。

### 4.3 关键设计决策（v2.0 相对 v1.0 的变化）

| 决策 | v1.0 | **v2.0** | 理由 |
|---|---|---|---|
| GUI | PySide6 独立程序 | **PyQt5 面板**（挂载主窗口） | 工具箱既有栈，禁止混用 Qt 绑定 |
| 3D | PyVista + pyvistaqt | **保留**（唯一新增依赖） | 坐标轴/锥体/箭头/文字开箱即用；matplotlib 3D 做静态图兜底 |
| 姿态转换 | 自研 ~200 行 + scipy 验证 | **直接用 `scipy.spatial.transform.Rotation`** | scipy 已是既有依赖，是该领域最成熟的实现；自研属"低级重复" |
| 路径搜索 | 自写 Dijkstra | **`scipy.sparse.csgraph.dijkstra`**（min_hops 另用 BFS） | 同上，复用成熟实现 |
| 账本格式 | 单文件 YAML（PyYAML） | **单文件 JSON（stdlib）** | 与 `calibration_batch_store` / `experiment_storage` 既有持久化约定一致；不占用新增依赖额度 |
| 注释保留 | 要求写出保留注释 | **不保留文件注释**；说明入 `note`/`source` 字段 | JSON 无注释；字段级备注是更可控的文档化方式 |
| 报告 | Jinja2 + Markdown | **python-docx（Word）+ Markdown 模板** | 复用 `experiment_word_export`；Jinja2 不在依赖清单内 |
| 打包 | PyInstaller | **Nuitka standalone**（ZIP 分发） | 与 `PACKAGING_GUIDE.md` 既有流程一致 |
| 误差/对比 | 仅 RSS 合成 | RSS 合成 + **对比/环路/限值复核** | 闭环"复核"显性需求 |

## 5. 数据模型设计

### 5.1 账本文件总体结构（JSON）

```json
{
  "schema": "coordinate_ledger",
  "schema_version": 1,
  "ledger": {
    "name": "ST-2026 载荷坐标系账本",
    "version": "1.0",
    "unit_default": "m",
    "angle_default": "deg",
    "quaternion_order": "wxyz",
    "euler_rotation": "intrinsic",
    "judge": { "warn_sigma": 1.0, "fail_sigma": 3.0 },
    "note": "示例账本"
  },
  "frames": [],
  "transforms": [],
  "limits": []
}
```

- 文件命名：`ledger_<型号>_<分系统>_v<版本>.json`，存放于 `runtime_paths.get_user_data_dir("坐标系账本")`。
- `schema` / `schema_version` 对齐 `schemas.py` 既有版本迁移机制，未知版本拒绝加载并提示升级。
- `judge` 为对比判定阈值（σ 倍数）：`warn_sigma` 缺省 1.0（黄），`fail_sigma` 缺省 3.0（红）；账本级统一配置，供 D7/D8/D9 共用。

### 5.2 坐标系（frame）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 全局唯一，`[A-Za-z0-9_-]{1,128}`（对齐 schemas 既有 ID 规则） |
| `name` | string | 否 | 中文名称 |
| `type` | enum | 否 | `body` / `payload` / `sensor` / `orbital` / `inertial` / `custom` |
| `axis` | enum | 是 | `Z_UP` / `Z_FORWARD` / `Y_UP` / `NED` / `ENU` |
| `unit` | enum | 否 | `m` / `mm`，缺省继承账本 |
| **`definition`** | string | 否 | **各轴物理定义文本**，如"X 沿飞行方向，Z 指向地心"（v2.0 新增，供评审引用） |
| `note` | string | 否 | 备注 |

### 5.3 变换（transform）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 全局唯一 |
| `from` / `to` | string | 是 | 含义见 2.1：产生 `T_to_from` |
| `rotation` | object | 是 | 见 5.4 |
| `translation` | [3] float | 是 | 子系原点在父系中的坐标（单位取 `to` 系 unit） |
| `sigma.t` | float | 否 | 平移误差 1σ（m），缺省 0 |
| `sigma.r_arcsec` | float | 否 | 旋转误差 1σ（角秒），缺省 0 |
| **`status`** | enum | 是 | `design` / `calibrated` / `as_built` / `obsolete`（v2.0 新增） |
| **`source`** | string | 否 | 来源标注：图纸号/报告号/表号，如 `ST-2026-JG-021 表3`（v2.0 新增） |
| **`effective`** | string | 否 | 生效说明：批次号 / 日期 / 工况（常温、低温）（v2.0 新增） |
| `note` | string | 否 | 备注 |

**多值共存与"当前有效值"规则（闭环痛点 1）**：

- 同一 `(from, to)` **允许多条** transform 记录（设计值、标定值、实测值各一条）；
- 查询缺省取状态优先级最高者：`as_built` > `calibrated` > `design` > `obsolete`（`obsolete` 永不自动选中）；
- 查询/报告**必须显示**当前值取自哪条记录（`id` + `status` + `source`）；
- 可显式指定 `status` 过滤，用于对比与历史值查看。

### 5.4 姿态的三种输入形式

```json
{ "type": "rpy", "value": [0, 0, 90], "order": "ZYX", "rotation_type": "intrinsic", "unit": "deg" }
{ "type": "quaternion", "value": [0.7071, 0, 0, 0.7071] }
{ "type": "matrix", "value": [1,0,0, 0,1,0, 0,0,1] }
```

- `rpy` 必须同时给出 `order` 与 `rotation_type`（2.2）；
- `quaternion` 顺序继承账本 `quaternion_order`，可覆盖；
- `matrix` 行优先 9 元，加载时校验正交归一（`RᵀR ≈ I`，`det ≈ 1`），超差报错并给出偏差量。

| `kind` | enum | 是 | `angle_between`（两轴夹角）/ `rotation_delta`（变换差异）/ `translation_delta` |
| `frames` | [2] string | 是 | 涉及的两个坐标系或两条 transform id |
| `expected` | float | 是 | 期望值 |
| `tolerance` | float | 是 | 公差（±） |
| `unit` | enum | 是 | `deg` / `arcsec` / `m` / `mm` |
| `note` | string | 否 | 需求出处，如 `SYS-REQ-0213` |

| 编号 | 功能 | 输入 | 输出 | 优先级 |
|---|---|---|---|---|

| D4 | 载荷指向计算 | 视轴 + 目标方向 + 参考系 | Az / El / 偏离角 | P1 |
| D5 | 姿态需求反算 | 目标指向 | 所需本体姿态四元数 | P1 |
| **D6** | **误差预算分解** | 两系路径 | 各段贡献表 + 方差占比 + 合成值 + **主导段标注** | **P0** |
| **D7** | **变换对比** | 两条 transform（或 status 对） | **分量级 δr/δt + 归一化判定 + 最大偏差项** | **P0** |
| **D8** | **环路闭合检查** | 全账本或指定回路 | 各回路闭合偏差 + 超差列表 | **P0** |
| D9 | 限值符合性检查 | limits 条目 | 计算值、偏差、通过/不通过 | P1 |

**D4 指向计算定义**（沿用 v1.0）：`v_t' = T_load_ref · v_target`，`Az = atan2(y,x)`，`El = asin(z)`，`θ = acos(v_load · v_t')`。

**D7 变换对比定义（分量级）**：

对比两条记录（典型：`design` vs `calibrated`），输出**两层视图**：

1. **参数视图**（供人核对录入是否抄错）：RPY / 四元数 / 平移的设计值与实测值逐项并列，看的是"参数变了多少"；
2. **本征差异视图**（**判定依据**，与参数化方式无关）：

```
ΔT = T_measured · inv(T_design)
δr = rotvec(ΔR) = [δrx, δry, δrz]   微小转角分解到 X/Y/Z 轴，单位 ″
δt = [δtx, δty, δtz]                 平移差分解到 X/Y/Z 轴，单位 mm
```

3. **归一化判定**（以该记录 σ 为基准，阈值可配，缺省 warn=1σ / fail=3σ）：

| 判据 | 颜色 | 含义 |
|---|---|---|
| \|z\| < 1（z = δᵢ/σ） | 绿 | 正常，属标定残差量级 |
| 1 ≤ \|z\| < 3 | 黄 | 关注，建议复测确认 |
| \|z\| ≥ 3 | 红 | 超差，需归因处置 |

4. **最大偏差项**：`argmax|zᵢ|`，直接回答"**哪一项偏大**"，并输出结论句；
5. 若 `limits` 中有对应条目，叠加 PASS / FAIL 判定。

> 旋转 σ 为各向同性标量，三轴分量共用 σ_r；平移同理共用 σ_t。该假设随报告页脚一并声明。

**D8 环路闭合定义**：以生成树 + 非树边枚举基本回路，逐回路计算 `T_loop = Π T_edge`，输出

```
e_rot = 等效转角(T_loop 的旋转部分)   单位 ″
e_trans = 平移部分模                  单位 mm
```

阈值缺省取回路各边 σ 的 RSS 合成值 ×3（3σ 原则），可配置。**输出"账本自检报告"**，是入账后的标准动作。

**D6 误差预算输出示例（含主导项识别）**

| 路径段 | 平移σ(mm) | 旋转σ(″) | 方差占比 | 对最终指向贡献(″) |
|---|---|---|---|---|
| body → star_tracker_1 | 0.5 | 2.1 | **69%** | 2.1 ← **主导段** |
| star_tracker_1 → camera_panchro | 0.6 | 1.4 | 31% | 1.4 |
| **合成（RSS）** | **0.78** | — | 100% | **2.52** |

**主导项识别**：按方差占比 `σᵢ²/σ_total²` 降序排列，标注最高段（上例为 `body → star_tracker_1`）。**若合成指向误差不达标，优先收紧主导段的安装/标定精度**——这是精度分配与复测决策的直接依据，而非盲目全线收紧。当主导段占比 > 50% 时，报告以醒目方式提示"该项主导合成误差"。

> 页脚固定声明：误差模型假设各段独立、各向同性；共因项（热变形等）不在 M1 范围。

### 6.5 复核功能（v2.0 重点，承接"复核"需求）

复核是一等公民，不是附属功能：

| 动作 | 功能 | 触发时机 |
|---|---|---|
| 入账后自检 | D8 环路闭合 | 保存账本后自动运行（后台），状态栏显示结果 |
| 标定后对比 | D7 变换对比 | 录入 `calibrated` 记录后，自动与 `design` 对比并高亮超限项 |
| 达标判定 | D9 限值检查 | 查询/对比界面一键执行 |
| 账本健康度 | A5 + D8 汇总 | 面板状态栏常显：`校验 0 错 1 警 │ 环路 3/3 闭合 │ 当前值来源已标注` |

### 6.6 设计值/实测值对比判读与操作思路

本节是工具的"用法设计"：不仅要求工具**算出**偏差，还要求它**指明哪一项偏大、给出处置思路**。

#### 6.6.1 多值语义

坐标系本身不带"值"；其"值"是它**相对父系的变换**。因此"设计值/实测值共存"落在变换记录上：

```
camera_panchro 相对 body 的安装关系
 ├─ T_body_cam_design      status=design     ← 图纸值，长期保留
 ├─ T_body_cam_cal_202605  status=calibrated ← 2026-05 批次标定值
 └─ T_body_cam_cal_202609  status=calibrated ← 2026-09 批次标定值（更新一次）
```

约定：**实测值入账时永不删除设计值**；错误记录置 `obsolete` 留痕，另补正确记录；同状态多条记录用 `effective` 区分批次。

#### 6.6.2 对比输出：两层视图 + 三级判定

D7 的输出在界面上固定为一张**分量对比表**（本征差异视图为准，参数视图并列可切换）：

| 分量 | 设计值 | 实测值 | 偏差 δ | σ | z=δ/σ | 判定 |
|---|---|---|---|---|---|---|
| 绕X (″) | — | — | +0.3 | 3.2 | 0.09 | 正常 |
| 绕Y (″) | — | — | −1.1 | 3.2 | 0.34 | 正常 |
| **绕Z (″)** | — | — | **−12.5** | 3.2 | **3.91** | **超差** |
| X (mm) | — | — | +0.02 | 0.8 | 0.03 | 正常 |
| **Y (mm)** | — | — | **+2.10** | 0.8 | **2.63** | **关注** |
| Z (mm) | — | — | −0.04 | 0.8 | 0.05 | 正常 |

表下固定输出**结论句**（由工具自动生成，报告与界面同文）：

> 最大偏差项：**绕 Z 轴 −12.5″（3.91σ，超差）**；次要关注：Y 向 +2.10 mm（2.63σ）；其余分量均在 1σ 内。建议优先核查 `body → camera_panchro` 绕 Z 向的安装/标定状态。

#### 6.6.3 实用操作流程

**流程 A｜设计入账（场景 A）**

```
按结构图纸录入 design 记录 → 账本保存 → 自动环路自检（D8）
   ├─ 环路闭合 ✓ → 账本自洽，可供查询引用
   └─ 环路不闭合 ✗ → 说明图纸间本身不一致（这就是复核产出！）
                      → 按回路分量定位可疑边，回图纸确认后再改账
```

**流程 B｜实测/标定入账（场景 B，最高频）**

```
录入 calibrated 记录（填 source 报告号、effective 批次）→ 保存
   → 自动触发 D7 与同 (from,to) 的 design 对比
   → 分量对比表 + 三级判定 + 最大偏差项提示
   ├─ 全绿 → 接受，账本"当前有效值"自动切换为 calibrated
   ├─ 有黄 → 复测确认；可暂接受但备注存疑
   └─ 有红 → 进入流程 C
```

**流程 C｜超差归因与处置（"哪一项偏大"之后做什么）**

```
看最大偏差项是旋转还是平移、偏在哪个轴
   → 查该记录 source（哪份报告/哪次装调）
   → 参考 6.6.4 判读经验表形成怀疑方向
   → 复测或复装 → 新值再入账（旧 calibrated 保留，effective 标批次）
   → 再对比，直到收敛或转遗留问题
注意：超差记录不得直接覆盖删除——留痕才能支撑复核结论
```

**流程 D｜误差预算驱动的精度分配（场景 E）**

```
计算目标指向误差 → D6 误差预算分解
   ├─ 合成值达标 → 输出分解表作论证依据
   └─ 合成值超标 → 看主导段（方差占比最高项）
                    → 只对主导段提标定/安装精度要求
                    → 重新录入该段 σ，复算直至达标
```

#### 6.6.4 判读经验表（偏差模式 → 可能原因 → 建议动作）

| 偏差模式 | 可能原因 | 建议动作 |
|---|---|---|
| 单轴旋转超差，其余轴正常 | 该轴向安装错位、标定基准错、螺钉未按力矩拧紧 | 专项核查该轴安装与标定基准 |
| 三轴旋转均匀偏小（均 < 1σ） | 正常标定残差 | 接受，更新状态 |
| 平移偏差集中在单一方向 | 安装面变形、垫片/支架误差 | 查结构件与安装面 |
| 旋转与平移偏差方向相关 | 同一次装调操作引入（如偏心安装） | 复装后复测，成对复核 |
| 多批次 calibrated 值彼此漂移 | 装拆反复、温度工况、标定不稳 | 查 effective 工况，必要时按工况分组 |
| 对比超差但环路闭合 ✓ | 该边自身值可疑，但全账本仍自洽 | 归因单边，勿动其他边 |
| 环路不闭合 ✗ | 至少一条边录入错误或图纸不一致 | 按回路逐边排查，优先查新改动边 |
| 与 limits 超差但对比全绿 | 限值期望本身录错，或限值适用于另一状态 | 核对 limits 的 expected 与适用状态 |

#### 6.6.5 界面与报告的呈现要求

- 分量对比表**红/黄/绿着色**，最大偏差项行加粗并置顶提示；
- 结论句为**自动生成**，界面与报告同文，不允许手写结论覆盖判定；
- 对比报告（F7）固定结构：对比对象（id/status/source）→ 分量对比表 → 结论句 → 处置建议（按 6.6.4 模式匹配，若命中则附上）→ 误差模型假设声明。

## 16. 附录

### 16.1 关键公式

```
齐次变换:   T = [R t; 0 1]        p' = T · p
逆变换:     T⁻¹ = [Rᵀ  -Rᵀt; 0 1]
路径合成:   T_A_C = T_A_B · T_B_C
误差传播:   σ_total = √(Σ σᵢ²)          （独立、各向同性假设）
欧拉角:     intrinsic ZYX → R = Rz(γ)·Ry(β)·Rx(α)（绕动轴）
指向角:     Az = atan2(v_y, v_x)；El = asin(v_z)；θ_off = acos(v_load·v_target)
对比:       ΔT = T₁·inv(T₂)；ΔR = angle(ΔT 旋转部)；Δt = |ΔT 平移部|
环路:       T_loop = Π T_edge ≈ I；e_rot = angle(R_loop)；e_trans = |t_loop|
```
