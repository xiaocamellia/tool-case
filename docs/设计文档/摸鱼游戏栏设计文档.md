## 1. 背景与目标

### 1.1 模块定位

工具箱主业是雷达工程计算（可视化、干涉仪仿真、测向校正、阵列设计、指标计算、试验记录等），摸鱼游戏栏是其中的休闲模块。副标题直接写在代码里（`game_panel.py:73`）：

```python
lbl_subtitle = QLabel('"科研狗的精神避难所"')
```

四款游戏均取雷达/信号题材：🧩 **频谱2048**（方块是频段，合并即频率翻倍）、🐍 **阵列贪吃蛇**（蛇身即阵元）、📡 **信号源猎手**（转动阵列找信号源）、💣 **干扰源扫雷**（雷即干扰源）。

### 1.2 设计目标

轻量好玩（单局 1~5 分钟、随时可停）、主题契合、无侵入性（不弹窗不推送）、不干扰主功能（纯 QWidget，无游戏引擎依赖）。

- **文档登记**：《便携化工具箱总体设计文档》§4.1 登记为页签 10（默认隐藏），§11.1 已知限制同此。

## 2. 总体架构

### 2.1 源码组织

单文件实现（无子包、无资源文件、无配置文件）：`radar_tool/game_panel.py`（约 39KB / 1028 行）。模块常量 `TILE_COLORS`/`FREQ_LABELS`/`SNAKE_COLORS` 在 `:26-51`；`GamePanel` 在 `:56-106`；四款游戏 `Game2048`/`ArraySnake`/`SignalHunter`/`MineSweeper` 分别在 `:111-285`/`:290-473`/`:478-744`/`:749-1021`；尾部 `:1024-1028` 导入 `QApplication`（扫雷取键盘修饰键）。模块级 `logger = get_logger('game_panel')`（`:23`），仅 `GamePanel.__init__` 输出 `logger.info('摸鱼游戏栏已创建')`。

### 2.2 游戏框架与组织方式

四款游戏是**四个相互独立的 `QWidget` 子类**，由 `GamePanel` 用一个 `QTabWidget`（`self.game_tabs`，`game_panel.py:80`）装载，页序固定：`Game2048()`「🧩 频谱2048」（`:88`）、`ArraySnake()`「🐍 阵列贪吃蛇」（`:89`）、`SignalHunter()`「📡 信号源猎手」（`:90`）、`MineSweeper()`「💣 干扰源扫雷」（`:91`）。无共享基类、无引擎抽象。

组织约定：各游戏在 `__init__` 调 `_init_ui()` 自建布局，状态全为实例属性（§3）；贪吃蛇/猎手/扫雷各持一个 `QTimer`，2048 纯事件驱动；贪吃蛇/猎手用普通 `QWidget` 作画布并把绘图函数挂到实例属性（§6.1）；键盘交互靠各自重写 `keyPressEvent`，焦点策略 `Qt.StrongFocus`。

## 3. 数据模型

### 3.1 总体原则：纯内存、无持久化

四款游戏全部状态都是 QWidget 子类上的实例属性，仅存于进程生命周期：不写文件、不用 `QSettings`、无 localStorage 等价物；无最高分、无成就、无进度保存；关闭程序不落盘。（`GamePanel` 底部提示"游戏进度自动保存…"是遗留文案，与实现不符，见 §8.1-#2。）

### 3.2 `Game2048`

| 属性 | 初值 | 含义 |
|---|---|---|
| `self.grid` / `self.score` / `self.game_over` | 4×4 全 0 / 0 / False | 棋盘（0=空，非 0 为 2 的幂频率值）；合并累加得分；终局后 `keyPressEvent` 直接返回 |
| `self.tiles` | `dict[(r,c)→QLabel]` | 16 个 80×80 方块 |
| `self.btn_reset`/`lbl_score`/`lbl_status`/`lbl_spectrum` | 控件 | 重开按钮、分数、状态、频谱条 |

`FREQ_LABELS`（`game_panel.py:41-46`）按 2 的幂逐档给频段短标签（2→`2.4G`、4→`4.8G`、8→`9.6G`、16→`19G`、32→`38G`、64→`77G`、128→`153G`、256→`307G`、512→`614G`、1024→`1.2T`、2048→`2.5T`、4096→`5.0T`…65536→`82T`），表外值显示 `str(v)`。`TILE_COLORS` 只到 2048，**4096 及以上回退 0 号格米灰色**（`_tile_style` 中 `TILE_COLORS.get(value, ('#cdc1b4', '#776e65'))`）。

## 4. 功能与算法设计

> 本节描述**实际实现**；早期设计稿（v1.0）未落地机制见 §6.3。

### 4.1 频谱2048（`Game2048`）

**玩法**：经典 2048——4×4 网格、方向键移动、同值合并翻倍；每次有效移动后随机生成新方块（90% 为 2、10% 为 4，`_add_random_tile` 中 `random.random() < 0.9`）；填满且无相邻同值时结束。方块文本是频段标签（`FREQ_LABELS`），合并即"频率翻倍"。

**移动算法**（四方向归约到"向左移"，`_move_left`，`game_panel.py:231-249`）：①压缩取行内非零值；②顺序扫描合并——`row[i]==row[i+1]` 时写 `row[i]*2`、`self.score += row[i]*2`、`i += 2`，否则 `i += 1`（每格每步最多并一次）；③补零到长度 4；④行变则 `moved = True`。方向复用（`:251-274`）：`_move_right`=`_reverse`→`_move_left`→`_reverse`；`_move_up`=`_transpose`→`_move_left`→`_transpose`；`_move_down`=`_transpose`→`_move_right`→`_transpose`。

**频谱条**（`_update_ui` 尾段，`:197-207`）：8 个频段桶，`idx = min(int(math.log2(v))-1, 7)`，桶值取 `min(v/2048, 1.0)`，按 `'▁▃▅▇█'[min(int(lv*5),4)]` 渲染字符条；初始占位文本 `'📊 频谱: ▁▂▃▅▇▆▃▂'`（`:142`）。

**终局与重开**：`_check_game_over`（`:276-285`）——有空格或横/纵相邻同值则未结束；结束后 `game_over=True`、状态栏 `'💀 游戏结束!'`、弹框显示最终分数，随后 **`reset_game()` 自动重开**。16 个方块经 `_tile_style` 用 QSS 上色（字号 <100→16px、<1000→13px、其余 10px）；键盘仅 ← → ↑ ↓；无定时器、暂停、撤销、最高分。

### 4.2 阵列贪吃蛇（`ArraySnake`）

**玩法**：30×20 网格贪吃蛇，吃食物 +1 节 +10 分，撞墙/撞己结束；**蛇身每节 = 一个阵元**，实时显示 `阵元: n | 孔径: n*0.5λ`（`_update_params`）。

**推进与碰撞**（`_tick`，`:372-400`）：`self.direction = self.next_dir`；新头 `nh=(hx+dx, hy+dy)`；越界或 `nh in self.snake[:-1]`（排除将让位的尾节）即 `_game_over()`；否则插入蛇头，吃到食物则 `score += 10`、`_spawn_food()` 并加速（`if self.timer.interval() > 80: self.timer.setInterval(max(80, self.timer.interval()-3))`，150ms 起、每食 -3ms、下限 80ms），否则 `snake.pop()`。`_spawn_food` 在未被蛇身占据的格子中 `random.choice`。

**结束与暂停**：`_game_over` 停表、提示 `'💀 撞到自己了! 得分: …'`（撞墙也复用此文案，§8.1）、弹框显示阵元数与得分后 **`start_game()` 自动重开**；`stop_game()` 暂停（按钮「▶ 继续」），`_paint` 在暂停且定时器未激活时画「⏸ 已暂停」遮罩。

**自绘与控制**（`_paint`，`:417-463`）：画布 `self.canvas = QWidget()`、`self.canvas.paintEvent = self._paint`，依次画网格线、蛇身（蛇头绿色大圆，其余节取 `SNAKE_COLORS[min(i,7)]` 并 `setAlpha(max(100, 255-i*15))` 渐隐）、食物（红圆+十字线）、暂停层。↑/W、↓/S、←/A、→/D 设 `next_dir`，空格开/停（`_toggle_game` 等价）；无"禁止反向"保护（§8.1）。

### 4.3 信号源猎手（`SignalHunter`）

**玩法**：圆形雷达视图上鼠标控制阵列指向，越接近信号源强度条越高；强度与角度满足条件时**自动锁定**；限时内找齐全部目标即通关。四款中唯一关卡制游戏，共 8 关（`max_level = 8`）。

**关卡设计**（`_init_level` 的 `configs`）：8 关按「目标数 `src` / SNR / 是否漂移 `move`」递进——关1: 1/25/固定（新手）、关2: 1/20/漂移（移动目标）、关3: 2/25/固定（双目标）、关4: 1/10/固定（低信噪比）、关5: 2/15/漂移、关6: 3/20/固定、关7: 2/8/漂移（强噪声）、关8: 3/5/漂移（终极）。`configs` 另含 `time` 字段（60/45/60/60/45/60/50/60）但**未被读取**，实际限时恒 60s（§3.4、§8.1）。

漂移（`_tick`）：每秒对未找到源 `s['angle'] = (s['angle'] + random.uniform(-3, 3)) % 360`（约 ±3°/s）。

**强度模型**（`_mouse_move`，`:606-637`）：指向角 `self.angle = math.degrees(math.atan2(dx, -dy)) % 360`（0°=正上方）；对每个未找到源取最大：

```python
diff  = min(abs(self.angle - s['angle']), 360 - abs(self.angle - s['angle']))  # 最小夹角
raw   = max(0, math.cos(math.radians(diff*2))**4)       # 主瓣 ±45°，四次余弦压低旁瓣
noise = random.gauss(0, 0.15 * (1 - self.snr/40))       # SNR 越低抖动越大
val   = max(0, min(1, raw + noise))
```

**自动锁定与计分**：`strength > 0.7` 且 `diff < 15` 时置 `found=True`、`target_count += 1`、`self.score += max(10, int(self.time_left))`。找齐则奖励 `int(self.time_left*2)`；`level < max_level` 时 `level += 1` 并 `_init_level(level)`（等「▶ 开始」）；打完第 8 关弹"🎉 恭喜!"并 `level=1`、`score=0` 归零。计时 `QTimer` 1000ms，到 0 则停表、按钮「▶ 重试」、弹"⏰ 时间用完了！"（不自动重开）。

**自绘与控制**（`_paint`，`:673-735`）：画布 min 360×360，`paintEvent`/`mouseMoveEvent` 均挂实例属性、`setMouseTracking(True)`；自绘背景圆、30° 刻度、阵列方向射线（0.75r 绿线+圆头）、5 个阵元示意点、已找到源 '✅'、强度波纹（`strength>0.1` 时半径 `8+int(strength*15)`）与虚线十字准星。移动鼠标转向；空格开/停/继续；「▶ 开始」按钮调 `_start_level()`（`_init_level(self.level)` 重新随机布源并计时，`setFocus`）。早期"←→ 微调 + 空格发射锁定"**未实现**：指向全靠鼠标，锁定为自动。

### 4.4 干扰源扫雷（`MineSweeper`）

**玩法**：标准扫雷，雷即干扰源，胜利提示"找到所有信号源"。左键揭开；数字 = 周围 8 格干扰源数；踩雷全盘揭示并结束；揭开所有**非雷**格子即胜（`_check_win`）；标记循环 未点→🚩→❓→未点。`_reveal_cell` 置 `state=1`，若 `board[r][c]==0` 则对 8 邻居中 `state != 1` 的递归揭开（越界、已点、雷位直接返回）。

**首点保护布雷**（`_place_mines`，`:889-910`）：首次点击才布雷，点击格及 8 邻居入 `safe` 集合跳过；`while placed < self.total_mines` 随机落雷，每布一颗同步给其 8 邻居 `board` 值 +1。

**标记与输入约定**（`_click_cell`，`:918-922`）：注释"右键菜单由 QPushButton 不支持，用 shift+点击代替"——`QApplication.keyboardModifiers() == Qt.ShiftModifier` 时走 `_flag_cell`。状态循环 0→2（旗，`flags_used+1`）→3（问号，`flags_used-1`）→0；「💣 剩余标记」显示 `total_mines - flags_used`。⚠️ 提示文案"右键标记 🚩"与实现不符（§8.1）。

**胜负与计时**：胜利（`board != -1 and state != 1` 计数为 0）→ 停表、弹"🎉 你找到了所有信号源！用时: {time_elapsed}s"、`_new_game()` 自动新局；失败 `_reveal_all()`（仅揭示雷位）、停表、弹"💥 你踩到干扰源了！"（不自动重开）；`_tick` 每秒 `time_elapsed += 1`；`Qt.Key_R` → `_new_game()`。

**网格重建**（`_new_game`，`:816-878`）：按难度取 `(rows, cols, total_mines)`、`cell_size = 32 if self.rows <= 16 else 28`，旧按钮 `deleteLater()` 后新建 `QGridLayout` 逐格 `QPushButton`（`clicked.connect(lambda checked, rr=r, cc=c: self._click_cell(rr, cc))`），经 `parent_layout.insertLayout(1, self.grid_widget)` 插回主布局（源码注释自述此处是简化处理），再重置 `board`/`state`/计时/`first_click`。⚠️ 旧网格布局未从父布局移除，反复开新局累积布局项（§8.1）。

**按钮样式**（`_btn_style`/`_update_button`）：未点灰底；雷 `💣` 红底；数字 1~8 八种颜色；旗 `🚩` 琥珀底；问号 `❓` 浅灰蓝底。

## 6. 关键实现与开发演进

### 6.1 Qt 游戏循环实现方式

无游戏引擎，纯 PyQt5 事件机制：

**（1）定时器驱动**（贪吃蛇/猎手/扫雷）：`ArraySnake` 初始 150ms 触发 `_tick`（每食 -3ms、下限 80ms）；`SignalHunter` 1000ms 触发 `_tick`（倒计时与漂移）；`MineSweeper` 1000ms 触发 `_tick`（计时，首点后启动）。

**（2）事件驱动**（2048）：无定时器，`keyPressEvent` 内完成移动→生成→判定。

**（3）自绘管线**：画布为普通 `QWidget`，绘图函数挂到**实例属性**覆写事件方法——`self.canvas.paintEvent = self._paint`（贪吃蛇 `:333` / 猎手 `:571`）、猎手另有 `self.canvas.mouseMoveEvent = self._mouse_move`（`:572`）与 `setMouseTracking(True)`。`_paint(self, event)` 内 `QPainter(self.canvas)` 开抗锯齿绘制并 `painter.end()`，需重绘时 `self.canvas.update()`。此写法省去为每个游戏建绘图子类，是本模块显著实现特征。

**（4）阻塞式弹框与进度保持**：结束/通关用 `QMessageBox.information(...)` 同步弹窗；2048/贪吃蛇/扫雷弹框返回后**立即自动重开**（`reset_game()`/`start_game()`/`_new_game()`），猎手的超时与通关等待用户点按钮。各游戏是独立页签页，未实现 `hideEvent`/可见性联动暂停，定时器仅在显式 `stop` 时停止——早期"切走自动暂停、回来继续"未落地（§6.3、§8.1）。

### 6.2 入口策略（GM-01，V1.2.1）

V1.1.1 的发布决定是"功能保留但不暴露入口"，做法是把主窗口两表注册项注释掉。**V1.2.1（GM-01）改为设置项开关**：注册项恢复，由 `settings_store.py` 的 `ui/show_game_tab`（默认 `false`）控制是否显示，运维不再需要改代码：

```python
            show_game = settings_store.get_bool('ui/show_game_tab', False)
            if show_game:
                self._tab_factories.append(self._create_game_tab)
                self._tab_names.append('摸鱼游戏')
```

要点：①零删除——`game_panel.py` 与 `_create_game_tab` 全保留；②懒加载自洽——未开启时两表长度 9 项一一对应，`run_smoke_test` 遍历 `_tab_names` 不触及游戏面板；③文档同步——《总体设计文档》§4.1 引注、README 功能表与「🔟 摸鱼游戏」章节保留介绍（有意保留）。

### 6.3 与早期设计的差异

早期《摸鱼游戏栏设计文档》（v1.0）是前瞻性玩法设计稿（抽屉式入口、Vue/Canvas 技术栈、成就、番茄钟等），落地实现做了大幅裁剪改造。逐项对照如下（"实现"列以 `game_panel.py` 为准）：

**A. 框架与入口**

| 早期设计 | 实际实现 |
|---|---|
| 顶部 🎮 图标 + 右侧抽屉（360px，ESC/遮罩关闭） | 主窗口页签，V1.2.1 起默认隐藏（设置项 `ui/show_game_tab` 可开启） |
| Vue 3 + Canvas + Pinia + localStorage；`games/` 多文件 | PyQt5 QWidget + QPainter/QSS；单文件 `game_panel.py`，无引擎、无持久化 |
| 快捷键 `G` 开关、`1-4` 切游戏 | 无全局快捷键，仅游戏内方向键/空格/R |

**B. 信号源猎手**

| 早期设计 | 实际实现 |
|---|---|
| 10 关（多径镜像、强干扰、相干陷阱、快速目标等） | **8 关**，仅 `src`/`snr`/`move` 组合，无干扰/多径/相干源概念 |
| 各关 45/60/90s 不同时限 | 配置表有 `time` 但**未读取**，统一 60s |
| ←→ 微调 + 空格"发射"锁定；技能（脉冲扫描/噪声抑制/空间谱）；三星评分；扫描线旋转、锁定扩散环 | 仅鼠标转向、**自动锁定**（强度>0.7 且夹角<15°）；无技能、无星级；静态重绘（刻度、方向线、5 阵元点、强度波纹、'✅'） |

**C. 频谱2048**：早期的 19.2G/38.4G/…/614.4G 全精度标签 → 实现为短标签 `19G`/`38G`/`77G`/`153G`/`307G`/`614G` 并延伸至 `1.2T…82T`；特殊方块（噪声方块/放大器/混频器）、技能（低通/高通/撤销）、最高分记录均无；网格底部动态频谱图 → 8 段字符频谱条即时计算。

**D. 阵列贪吃蛇**：4 种食物（📡+1/🌐+2/⚡反向/✨穿墙）→ 单一食物（红十字圆靶）+1 阵元 +10 分；理论分辨率/栅瓣风险显示、栅瓣惩罚（栅瓣鬼）、空间平滑 buff（×1.5）均未实现，仅 `阵元: n | 孔径: n*0.5λ`；霓虹/像素风 → 深蓝底圆点蛇身。

**E. 干扰源扫雷**：双实体（信号源 ✅ 与干扰源 💣 都需正确标记）→ 标准扫雷（雷=干扰源、数字=相邻雷数、胜利=揭完非雷格）；难度 4 档（含专家 30×30）→ 3 档；右键三态标记 → **Shift+左键**（文案仍写"右键"）；特殊格（相干源/多径/盲区）、技能（MUSIC 扫描/波束形成/人工标记）、数字色表信号强度均无。

**F. 通用系统**：成就、番茄钟联动、持久化、音效——**均未实现**（底部"自动保存"文案与实现矛盾）。

**G. 实现层新增/偏离早期稿的真实行为**：①三款游戏结束后**自动重开**（`reset_game()`/`start_game()`/`_new_game()`）；②贪吃蛇**动态加速**（150→80ms）；③猎手**自动锁定**与 `cos(diff*2)^4` 主瓣 + SNR 联动高斯噪声强度模型；④扫雷**首点 3×3 安全区**；⑤`SignalHunter.active` 补建（注释"缺少此属性导致报错"），说明开发中经历过一次缺属性报错修复。
