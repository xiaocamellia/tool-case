### 关键技术决策（有长期价值）
1. **方向**：仪器面板而非 SaaS 仪表盘。主色 `#2F6A8C`（低饱和钢青蓝），层次只靠底色差 + 1px 描边 + 字重（QSS 无 box-shadow），页签用 2px 下划线而非 pill。
2. **窄屏页签**：实测 `QFontMetrics('Microsoft YaHei',10)` 下 9 个全称页签占 1219px（+padding 1471px），
   规范原估 689/941px 是错的。单纯减 padding 无解 → 采用 `<1280px` 切短名 + 9pt + 8px 内边距（942px），
   全称由 tooltip + 每页 PageHeader 承载。
3. **表格 elide**：Consolas 10pt 下 `-0.052` 占 78px，`::item padding 0 10px` + 88px 列只剩 68px 内容区，
   会被 Qt 省略成 `-0....`。修法 = 数值列等宽右对齐 + `ResizeToContents` + item padding 降到 6px。
4. **matplotlib 中文方框**：根因是 `font.family` 回退链里 SimSun/STSong 本机缺失，落到 DejaVu Sans 无 CJK 字形。

5. **结果卡向后兼容**：`ResultCard` 必须实现 `toPlainText()`（驼峰），因为 6 个测试文件用
   `widget.result_text.toPlainText()` 断言；平铺文本不得丢说明性文字、不得改数值可断言子串
   （`1000` / `-90` / `接近正侧射` / `必须大于 0`）。禁止千分位、禁止 U+2212 排版减号。
6. **不改造** `interferometer_sim.txt_stats` / `compare_analysis.txt_cmp_stats`：

## BugFix：matplotlib findfont 警告刷屏

- **现象**：用户反馈运行时控制台被
  `findfont: Font family 'Microsoft YaHei UI' / 'Noto Sans CJK SC' / 'Source Han Sans SC' not found.`
  反复刷屏（数百条）。这是上午修中文方框时引入的回归。
- **根因**：`app_config.py` 的 `_CJK_FONT_STACK` 为「便携」写死了 7 个候选名，其中 3 个本机不存在。
  `font.family` 是**有序列表**，findfont 每渲染一段文字都会遍历整条链，并对每个缺失名打一条
  warning。实测 2×2 子图单次 draw 就 147 条（49 次文字查找 × 3），多子图 / 重绘时成倍累积。
- **修复**：字体链不再写死，改为 `resolve_cjk_font_stack()` 运行时用
  `font_manager.fontManager.ttflist` 过滤本机实有字体族：
  - `_CJK_FONT_CANDIDATES` 扩到 15 个，覆盖 Windows / macOS / Linux；
  - 候选全部落空时，从系统字体名里捞含 CJK 关键字（`yahei/hei/song/cjk/han/...`）的族；
  - fontManager 不可用则只留 `DejaVu Sans`（宁可缺字形，也不制造上百条告警）；
  - 保留 `_CJK_FONT_STACK` 原名不破坏引用，另暴露公开别名 `CJK_FONT_STACK`。
- **本机生效链**：`['Microsoft YaHei','SimHei','Microsoft JhengHei','DengXian','SimSun','STSong','DejaVu Sans']`；
  解析到 `C:\Windows\Fonts\msyh.ttc`，「中/频/率」字形齐全；findfont / Glyph 告警均为 0。
- **长期经验**：matplotlib `font.family` 链里**不能有本机不存在的名字**；跨机器分发的软件字体链必须
  运行时探测而非写死；`font.family` / `font.sans-serif` / `font.serif` 三者必须一致，否则中文各自回退。
